# بازبینی مستقل QA و رگرسیون — ردیف ۱۱

تاریخ: ۲۰۲۶-۱۰-۲۵. هدف: تشخیص آنچه واقعاً اجرا شده از نتیجه مطالعه کد، تطبیق یافته‌های تخصصی با پوشش تست، و تعریف رگرسیون قابل سنجش. منبع برنامه تغییر نکرد؛ migration، seed، RefreshDatabase، پرداخت یا تغییر داده اجرا نشد.

## نتیجه

صفحه در سناریوهای معمول جستجو و اندازه‌های بررسی‌شده قابل استفاده است، اما مجموع رفتارها تأیید نمی‌شود: اشکال مرتب‌سازی، حذف زیردسته‌ها و متادیتای اختصاصی، از دست‌رفتن تمرکز پس از پاک‌کردن، canonical صفحه دوم و ایراد معنایی JSON-LD شواهد اجرایی دارند. ایرادهای مجوز قیمت، invalidation کش و پایداری آیکون همچنان باید پیش از پذیرش نسخه اصلاح شوند و با سناریوی نقش/داده مربوط آزموده شوند. این بازبینی صرفاً ارزیابی است؛ هیچ یافته‌ای به‌عنوان اصلاح‌شده بسته نشده است.

## آزمون‌های واقعاً انجام‌شده

### آزمون‌های این عامل

- در نقش فرانت‌اند، تابع `norm` از فایل واقعی Blade استخراج و با Node اجرا شد: `كي` و `کی` برابر؛ نیم‌فاصله و فاصله در `سرویس‌ها`/`سرویس ها` برابر؛ نبود فاصله در `سرویسها` با حالت نیم‌فاصله برابر نیست. مورد آخر به‌تنهایی باگ قطعی تلقی نشد.
- در این نقش QA، `sort-check.json` با Node parse و دو آرایه `newestProducts` و `oldestProducts` مقایسه شدند: برابرند. داده شامل عنوان‌های دیگر صفحه نیز هست؛ این مقایسه جایگزین انتخاب صحیح selector کارت‌ها نیست، ولی با مشاهده مستقیم عامل اصلی و کنترلر همیشه `latest()` همخوان است.
- `rendered-schema.json` با Node parse شد. خود JSON قابل parse است اما `parsed` کلید `@context` ندارد؛ به‌جای آن کلیدی با متن واقعی `<?php $__contextArgs ... ?>` وجود دارد و مقدار آن `https://schema.org` است. این شاهد مستقلاً از artifact خوانده شد. JSON.parse موفق برای تأیید JSON-LD کافی نیست.
- فایل تست‌ها و گزارش‌های موجود مطالعه شدند؛ آزمون PHPUnit/Pest اجرا نشد.

## پوشش موجود تست‌ها و شکاف قابل اقدام

### P2 — تست‌های فعلی می‌توانند با وجود شکست قرارداد صفحه سبز شوند

- محل: `tests/Feature/GuestPagesTest.php:56`، `:65` و `:143`.
- تست index فقط ۲۰۰ بودن پاسخ را assert می‌کند. تست show یک دسته می‌سازد و فقط status را می‌سنجد؛ فرزند، چند محصول با ترتیب متمایز، قیمت با نقش‌های مختلف یا متادیتا را نمی‌سنجد. تست sitemap فقط status و وجود header را می‌سنجد.
- سناریوی اثبات شکاف: canonical نادرست، حذف بخش زیردسته، title عمومی، ترتیب نامعتبر یا JSON قابل parse با `@context` خراب هیچ‌کدام الزاماً status=200 را تغییر نمی‌دهند؛ بنابراین این assertions به رفتارهای شکسته حساس نیستند.
- پیشنهاد: پس از اصلاح هر مورد، assertion رفتار همان قرارداد به تست مرتبط اضافه شود. ساخت تست صرفاً مشابه implementation یا گسترش بی‌هدف suite لازم نیست. برای مرورگر، جستجوی Alpine و تمرکز باید تست مرورگر داشته باشند؛ تست HTTP به‌تنهایی کافی نیست.
- `GuestPagesTest` در خط ۱۲ از `RefreshDatabase` استفاده می‌کند. این مجموعه علیه پایگاه داده فعلی اجرا نشد؛ برای اجرای بعدی اتصال تست ایزوله و امکان پاک‌سازی کامل آن باید از قبل تأیید شود.

## تفاوت نقش متخصص با تأیید اجرایی

- گزارش query/Cache شواهد profiling مستقل دارد؛ این QA تعداد queryها را دوباره اندازه نگرفت. انتظار آزمون پس از اصلاح باید این باشد که دسترسی مکرر به شمارش دسته query متناسب با تعداد گره ایجاد نکند.
- نسخه محلی DB در گزارش استقرار `10.4.32-MariaDB` ثبت شده؛ سناریوهای تاریخ/SQL باید روی همین خانواده یا DB هدف واقعی تکرار شوند. تست SQLite جایگزین بررسی سازگاری MariaDB/MySQL نیست.
- پیش از پایان جمع‌بندی، گزارش اسکیما باید با شاهد واقعی `@context` خراب به‌روزرسانی شود. نسخه قبلی `schema.md` و برداشت گزارش AI از سالم‌بودن ساختار، بر مطالعه کد تکیه داشته و نتیجه اجرایی artifact آن را محدود می‌کند. این مسئله به عامل اصلی برای هماهنگی بازبین مربوط اعلام شد.

## اجرا‌نشده‌ها

اجرای suite کامل/Feature با DB، تست نقش واردشده، آزمون نوشتن داده/commit/rollback/concurrency، cache clear، migration/seed، مرورگر مستقل این عامل، صفحه‌خوان واقعی، zoom ۲۰۰/۴۰۰ درصد، landscape، دستگاه iOS/Android واقعی، نسخه‌های دیگر مرورگر، production، Search Console، Rich Results Test، Lighthouse/Core Web Vitals، شرایط محدودیت هاست و redirect واقعی Apache انجام نشدند. هیچ نتیجه «همه تست‌ها پاس شد» یا آمادگی انتشار از این بررسی صادر نمی‌شود.
