# بازبینی مستقل SEO صفحه دسته‌بندی‌ها

تاریخ: ۲۰۲۶-۱۰-۲۵. دامنه: `/categories`، صفحه بلافصل `/categories/{slug}`، layout عمومی، مسیرها، sitemap و robots. روش: مطالعه فقط‌خواندنی کد؛ فایل اجرایی پروژه تغییر نکرد. این گزارش از مشاهده مرورگر یا Search Console به‌عنوان شواهد مستقل استفاده نمی‌کند. بررسی اسکیما و جستجوی گوگل نقش‌های جداگانه دارند.

## یافته‌های قابل اقدام

### P2 — متادیتای اختصاصی دسته در صفحه مقصد مصرف نمی‌شود

- محل: `resources/views/pages/categories/show.blade.php:3` و `:4`؛ `resources/views/layouts/app.blade.php:9` و `:11`؛ `app/Http/Controllers/Web/CategoryController.php:126`.
- علت: show از `@section('title', ...)` و `@section('description', ...)` استفاده می‌کند، اما layout هیچ‌کدام را yield نمی‌کند و فقط متغیرهای `$seoTitle`، `$pageTitle` و `$seoDescription` را می‌خواند. کنترلر show این متغیرها را ارسال نمی‌کند.
- بازتولید: از فهرست دسته‌ها وارد هر دسته شوید، یا برای دسته `seo_title` و `seo_description` اختصاصی ذخیره کنید؛ `<title>` همچنان نام عمومی برنامه است و description عمومی layout باقی می‌ماند. Open Graph نیز title عمومی و description خالی می‌گیرد. تغییر عنوان H1 این مشکل را رفع نمی‌کند.
- اثر: صفحات دسته‌های متفاوت اطلاعات اختصاصی ذخیره‌شده را در head ندارند؛ پیش‌نمایش اشتراک‌گذاری نیز دسته را معرفی نمی‌کند. هیچ ادعایی درباره رتبه فعلی یا افت قطعی ترافیک مطرح نیست.
- اصلاح: متغیرهای مورد انتظار layout را از کنترلر show ارسال کنید و fallback نام/توضیح دسته را اعمال کنید، یا قرارداد layout را به مصرف sectionهای موجود مجهز کنید. راه‌حل انتخاب‌شده باید title، description و OG را هم‌زمان پوشش دهد.

### P2 — مسیر لینک داخلی به زیردسته‌های صفحه مقصد حذف می‌شود

- محل: `resources/views/pages/categories/show.blade.php:51` و `:55`؛ `app/Http/Controllers/Web/CategoryController.php:76` و `:126`؛ `resources/views/pages/categories/index.blade.php:42` و `:207`.
- علت: کنترلر رابطه `children` را بارگذاری می‌کند اما متغیر `$subcategories` مورد استفاده Blade را نمی‌فرستد. شرط `isset` باعث می‌شود بخش لینک زیردسته‌ها بی‌صدا حذف شود.
- بازتولید: وارد یک دسته دارای زیردسته شوید؛ بخش زیردسته‌ها نمایش نمی‌یابد. در index نام نوه در جستجو لحاظ می‌شود، ولی لینک نمایش‌داده‌شده به فرزند می‌رود؛ در مقصد راه مرور به نوه وجود ندارد.
- اثر SEO: لینک داخلی مورد انتظار برای ادامه درخت دسته‌ها در خروجی مقصد وجود ندارد. وجود URLهای فعال در sitemap این نقص ناوبری داخلی را جبران نمی‌کند.
- اصلاح: حلقه و شرط Blade را از `$category->children` تغذیه کنید یا `$subcategories` را صریحاً ارسال کنید. این همان یافته فرانت‌اند است و در تجمیع گزارش نباید دوباره شمرده شود.

### P3 — عنوان Open Graph فهرست با عنوان اختصاصی صفحه هماهنگ نیست

- محل: `app/Http/Controllers/Web/CategoryController.php:63`؛ `resources/views/layouts/app.blade.php:9` و `:16`.
- علت: index فقط `$pageTitle` را تعیین می‌کند. `<title>` آن را به عنوان اصلی اضافه می‌کند اما `og:title` فقط `$ogTitle`، سپس `$seoTitle` و سپس نام برنامه را می‌خواند.
- بازتولید: head صفحه `/categories` را بخوانید؛ عنوان سند مخصوص دسته‌بندی‌هاست ولی `og:title` صرفاً نام عمومی برنامه است.
- اصلاح: `$ogTitle` یا `$seoTitle` مناسب از کنترلر بفرستید، یا fallback مشترک عنوان سند و OG را در layout تعریف کنید.

## موارد بررسی‌شده بدون یافته مستقل برای index

- مسیر index عنوان اختصاصی از `$pageTitle`، description مشخص و canonical صریح `route('categories.index')` دارد.
- نام ریشه‌ها و فرزندان با لینک‌های واقعی `href` در HTML سرور قرار می‌گیرند؛ جستجوی Alpine تنها نمایش را تغییر می‌دهد و برای تولید اولیه این لینک‌ها لازم نیست.
- یک H1 برای موضوع صفحه وجود دارد و عنوان دسته‌های ریشه H2 است.
- index در sitemap ثابت و دسته‌های فعال در sitemap دسته‌ها لحاظ شده‌اند. خروجی واقعی sitemap و اعتبار URLهای محیط production در این بازبینی درخواست نشده است.

## ارجاع به نقش جستجوی گوگل و محدودیت‌ها

- `public/robots.txt:11` الگوی `Disallow: /*?` دارد. صفحات محصولات هر دسته با `paginate(16)` در کنترلر و `links()` در Blade دارای query string صفحه‌بندی‌اند. این ترکیب باید توسط نقش جستجوی گوگل مستقلاً بررسی شود.
- canonical پیش‌فرض layout در `resources/views/layouts/app.blade.php:23` از `url()->current()` استفاده می‌کند؛ برای show با `?page=2` پارامتر page در canonical حفظ نمی‌شود. تصمیم و اثر صفحه‌بندی در گزارش نقش گوگل روشن شود؛ اینجا به‌عنوان یافته تکمیلی بدون ارزیابی موتور جستجو ثبت شده است.
- index/show در این بازبینی تغییر نکردند؛ بررسی redirect، 301/308، انتقال slug قدیمی، Search Console، crawl زنده، rich result و Core Web Vitals انجام نشد.
- هیچ تضمینی درباره نمایش، رتبه یا انتخاب snippet توسط موتورهای جستجو داده نمی‌شود.
