# بازبینی مستقل جستجوی گوگل

تاریخ: ۲۰۲۶-۱۰-۲۵. دامنه: فهرست `/categories`، مقصد `/categories/{slug}`، صفحه‌بندی، robots، sitemap و حفظ URL قدیمی دسته. روش: بررسی فقط‌خواندنی کد و تطبیق با مستند رسمی Google؛ بدون تغییر منبع یا داده و بدون درخواست به production. یافته متادیتای show در گزارش SEO جداگانه آمده و اینجا تکرار نمی‌شود.

## یافته‌ها

### P2 — منع عمومی query string، خزیدن صفحه‌های بعدی دسته را مسدود می‌کند

- محل دقیق: `public/robots.txt:11`؛ `app/Http/Controllers/Web/CategoryController.php:116`؛ `resources/views/pages/categories/show.blade.php:121`.
- شواهد: قانون `Disallow: /*?` برای همه ربات‌ها تعریف شده، اما محصولات دسته با `paginate(16)` و لینک‌های `?page=2` و بالاتر تقسیم می‌شوند. هیچ استثنای Allow مخصوص صفحه‌بندی دسته وجود ندارد.
- بازتولید: دسته‌ای با بیش از ۱۶ محصول قابل نمایش را باز کنید؛ لینک صفحه دوم را با قواعد robots همین مخزن تطبیق دهید. `/categories/{slug}?page=2` مشمول منع است.
- اثر: Googlebot اجازه خزیدن محتوای صفحه دوم را از این URL ندارد؛ این به معنی تضمین حذف خود URL از نتایج نیست. وجود محصول در sitemap مستقل، مشکل منع خزیدن صفحه‌بندی دسته را رفع نمی‌کند.
- پیشنهاد: سیاست منع query را به پارامترهای غیرضروری مانند مرتب‌سازی/فیلتر محدود کنید و URLهای صفحه‌بندی مورد نیاز را قابل خزیدن نگه دارید. استثنا نباید ناخواسته تمام ترکیب‌های فیلتر را آزاد کند.
- مبنای رسمی: مستند pagination گوگل توصیه می‌کند صفحات متوالی از لینک واقعی قابل دسترسی باشند؛ مستند robots تفاوت منع خزیدن با منع ایندکس را روشن می‌کند. منابع رسمی در انتهای گزارش آمده‌اند.

### P2 — canonical صفحه دوم و بالاتر به صفحه اول اشاره می‌کند

- محل دقیق: `resources/views/layouts/app.blade.php:23` و `app/Http/Controllers/Web/CategoryController.php:126`.
- شواهد: show مقدار `$canonical` ارسال نمی‌کند؛ fallback از `url()->current()` استفاده می‌کند و query string از آن حذف می‌شود. محتوای محصولات در صفحه دوم متفاوت است، اما canonical همان `/categories/{slug}` بدون `?page=2` است.
- بازتولید: به `/categories/{slug}?page=2` دسته دارای بیش از ۱۶ محصول بروید و canonical خروجی را بخوانید. ارزیابی این مورد بر اساس قرارداد helper در کد است؛ HTML صفحه دوم در این نقش مستقلاً دریافت نشد.
- اثر: سیگنال canonical، صفحه دوم را معادل صفحه اول معرفی می‌کند. رفع robots به‌تنهایی این ناسازگاری را رفع نمی‌کند.
- پیشنهاد: canonical صفحه‌بندی را با حفظ تنها پارامتر معنایی `page` بسازید؛ برای صفحه اول URL تمیز و برای صفحه‌های بعد URL مستقل داشته باشید. پارامترهای tracking یا مرتب‌سازی را بی‌دلیل وارد canonical نکنید.
- مبنای رسمی: مستند Google صریحاً توصیه می‌کند هر صفحه یک توالی صفحه‌بندی canonical خودش را داشته باشد و canonical تمام توالی به صفحه اول داده نشود.

### P2 — ویرایش slug دسته، URL قدیمی را بدون انتقال دائمی رها می‌کند

- محل دقیق: `app/Livewire/Admin/Categories/Create.php:215`، `:342` و `:366`؛ `routes/web.php:139`؛ `app/Models/Category.php:51`.
- شواهد: فرم فعال ویرایش admin مقدار slug جدید را اعتبارسنجی و روی همان دسته update می‌کند. route binding فقط slug فعلی را پیدا می‌کند. در جستجوی کد، نگاشت redirect قدیمی برای محصول و تأمین‌کننده موجود است ولی معادل دسته یافت نشد. ستون `legacy_id` دسته، نگاشت URL یا redirect نیست.
- بازتولید پیشنهادی در fixture جداگانه: slug دسته فعال را از `old-category` به `new-category` تغییر دهید؛ `/categories/old-category` دیگر bind نمی‌شود و مسیر برنامه برای آن 301/308 به URL جدید ندارد. این بازتولید تغییردهنده داده در این بازبینی اجرا نشد.
- اثر: لینک داخلی کش‌شده، bookmark و لینک خارجی URL قبلی به مقصد جدید منتقل نمی‌شوند. شدت روی سناریوی تغییر slug است؛ اثباتی درباره تعداد URLهای قدیمی شکسته فعلی یا ترافیک آن‌ها نداریم.
- پیشنهاد: یا تغییر slug دسته منتشرشده را ممنوع کنید، یا نگاشت تاریخی مستقل ایجاد کنید که هر slug قدیمی را مستقیم با 301 یا 308 به slug جاری همان دسته ببرد. مالکیت slugهای تاریخی، عدم استفاده مجدد برای دسته دیگر، جلوگیری از حلقه و هدایت مستقیم به آخرین مقصد را لحاظ کنید. پس از تغییر، لینک‌های داخلی و sitemap نیز باید URL جاری را داشته باشند.
- مبنای رسمی: Google برای جابه‌جایی دائمی URL، redirect سمت سرور 301/308 و مقصد نهایی مستقیم را توصیه می‌کند.

### P3، مشروط به داشتن تصویر — URL تصویر sitemap دسته توسط robots منع می‌شود

- محل دقیق: `public/robots.txt:13`؛ `app/Models/Category.php:230`؛ `app/Http/Controllers/SitemapController.php:74`؛ `resources/views/sitemap/urls.blade.php:10`.
- شواهد: تصویر دسته از `/storage/{image_path}` ساخته و در sitemap تصویر قرار می‌گیرد؛ robots کل `/storage/` را منع می‌کند.
- بازتولید: برای دسته‌ای با `image_path` غیرخالی، آدرس image:loc sitemap را با قواعد robots تطبیق دهید؛ مشمول منع است. وجود چنین دسته‌ای در داده فعلی توسط این نقش مستقلاً بررسی نشد.
- پیشنهاد: محل فایل‌های عمومی تصویر دسته/محصول را با سیاست robots هماهنگ کنید. فقط URL عمومی لازم قابل خزیدن شود؛ حذف دسته‌جمعی محدودیت‌ها بدون شناخت محتوای storage پیشنهاد نمی‌شود.

## گزارش صریح مسیر، redirect و JSON-LD

| مورد | نتیجه بررسی |
| --- | --- |
| canonical نهایی index | در کنترلر `:65` صریحاً `route('categories.index')` است؛ JSON-LD index در Blade `:10` و breadcrumb `:15` از همان route ساخته می‌شوند. همخوانی کدی برقرار است. |
| URL آیتم‌های JSON-LD | `index.blade.php:25` و لینک کارت `:196` هر دو `route('categories.show', $cat->slug)` را مصرف می‌کنند؛ تفاوت مسیر در کد دیده نشد. اعتبار اسکیما نقش دیگری دارد. |
| canonical نهایی show | برای URL بدون query همان URL جاری است؛ برای صفحه‌بندی ایراد بالا وجود دارد. host و scheme واقعی production تأیید نشده است. |
| 301/308 عمومی سرور | `public/.htaccess:113` تا `:114`، HTTP را به HTTPS با 301 می‌برد؛ `:125` تا `:127` اسلش پایانی را با 301 حذف می‌کند. 308 در این محدوده یافت نشد. |
| زنجیره redirect | با همین تنظیم Apache، URL فرضی HTTP دارای اسلش انتهایی می‌تواند دو مرحله HTTP→HTTPS و سپس حذف slash داشته باشد. اجرا روی سرور واقعی، تعداد hop واقعی و header Location بررسی نشده‌اند؛ این مورد به‌تنهایی یافته بحرانی تلقی نشده است. |
| حلقه redirect | در منطق route دسته redirect اختصاصی وجود ندارد؛ آزمون زنده حلقه و رفتار TLS proxy/هاست انجام نشد. نبود حلقه production تأیید نمی‌شود. |
| حفظ URL قدیمی دسته | در سطح برنامه نگاشت پیدا نشد؛ سناریوی تغییر slug یافته P2 است. نگاشت احتمالی بیرون مخزن در CDN/پنل هاست بررسی نشده است. |
| sitemap | index در sitemap ثابت و دسته‌های فعال در sitemap دسته‌ها قرار می‌گیرند. کد ساخت XML خوانده شد؛ HTTP زنده sitemap، وضعیت Google Search Console و cache فعلی sitemap بررسی نشد. |

## منابع رسمی و محدودیت اعتبارسنجی

منابع رسمی Google که در این نقش خوانده شدند؛ URLها صرفاً مرجع مستندات‌اند و به معنی بررسی production نیستند:

- Pagination، بخش Use URLs correctly و Link pages sequentially: `https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading`
- تفسیر robots، بخش disallow و URL matching: `https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec`
- جابه‌جایی URL و redirect دائمی و زنجیره: `https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes`

Search Console، URL Inspection، crawl زنده، وضعیت ایندکس واقعی، رتبه، Core Web Vitals و درخواست‌های production اجرا نشده‌اند. آزمون نوشتن داده برای تغییر slug نیز اجرا نشد. از این گزارش نمی‌توان رتبه یا نمایش در نتایج گوگل را تضمین یا افت ترافیک فعلی را نتیجه گرفت.
