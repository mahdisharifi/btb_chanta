# پردازش احتمالی مدل متنی

## Feature flag و شروط

پردازش Stable Partial با متغیر `ENABLE_SPECULATIVE_LLM=false` خاموش است. فعال‌کردن آن هزینهٔ API و ارسال متن موقت کاربر به provider را در پی دارد؛ پس از فعال‌سازی باید مجوز privacy و بودجهٔ محصول جداگانه بررسی شوند.

در حالت روشن، coordinator فقط Stable Prefix حداقل ۲۴ نویسه را می‌بیند؛ حداکثر یک درخواست برای هر turn و یک درخواست هم‌زمان، حداقل ۷۵۰ ms فاصله و timeout برابر ۲۵۰۰ ms. این حدود، تنظیمات محافظه‌کارانهٔ فعلی هستند و هنوز با دادهٔ واقعی هدف‌سخت‌افزار کالیبره نشده‌اند.

## اعتبار پاسخ

- درخواست حدسی از متن پایدار و context snapshot مستقل ساخته می‌شود.
- تغییر Partial، تغییر Stable Prefix یا barge-in، controller آن درخواست را abort می‌کند.
- پاسخ حدسی مستقیم به UI یا پلیر نمی‌رود.
- استفادهٔ مجدد فقط وقتی مجاز است که متن Final دقیقاً با متن حدسی و context key دقیقاً با snapshot اولیه برابر باشد.
- در غیر این صورت پاسخ کنار گذاشته می‌شود و مسیر عادی Final اجرا می‌شود.
- هیچ tool call یا عملیات محصولی به پاسخ حدسی متصل نیست.

API key فعلی همچنان از مرورگر به provider ارسال می‌شود و فقط در حافظهٔ tab نگه‌داری می‌شود. این تغییر API key را به backend منتقل نمی‌کند. برای محصول چندکاربره، backend credential broker مسیر ایمن‌تری است و مهاجرت آن هنوز انجام نشده است.

## آزمون

`node --test tests/speculative_llm.test.cjs` رفتار پیش‌فرض خاموش، reuse دقیق، invalidation، سقف درخواست و abort را با Mock Provider بررسی می‌کند. هیچ درخواست واقعی آروان در تست اجرا نمی‌شود.
